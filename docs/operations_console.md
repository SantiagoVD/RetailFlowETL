# Operations Console

RetailFlow's web console is an operational surface over the existing serverless ETL. It does not replace or synchronously call the ETL Lambda.

## Architecture

```text
React + TypeScript + Vite
        |
        | HTTPS
        v
API Gateway HTTP API
        |
        v
retailflow-api-dev
        |
        +-- presigned POST -> existing S3 input/<dataset>/<upload_id>/
        +-- read metadata/runs/
        +-- read gold/ and quarantine/
        +-- presigned GET for downloads
                              |
                              v
                    retailflow-etl-dev
```

The API is deployed in the separate `retailflow-web-api` stack. The ETL remains in `retailflow-serverless-etl`, with the existing bucket and S3 notification preserved.

## API Contract

`POST /uploads` accepts `dataset`, `file_name` and `content_type`. It returns an `upload_id`, a backend-built object key, presigned POST URL and form fields. The key format is:

```text
input/<dataset>/<upload_id>/<file_name>
```

`GET /uploads/{uploadId}` returns `PROCESSING` until the ETL writes a matching run metadata object. It then returns `SUCCESS`, `FAILED` or `SKIPPED`. A skipped run includes `original_run_id`.

`GET /runs` reads `metadata/runs/` and sorts by `start_time` descending. Run detail returns all output keys and counts. Result preview reads the primary Gold Parquet with PyArrow and caps the response at 100 rows. Error preview reads Quarantine Parquet and returns an aggregated error-code summary. Download routes return 5-minute S3 presigned GET URLs.

## Frontend Routes

```text
/             New upload and asynchronous processing
/runs/:runId  Metadata, Gold preview, quality summary and downloads
/about        Architecture and cost-control notes
```

The UI does not expose a run-history screen. It polls `GET /uploads/{uploadId}` every 2.5 seconds for up to five minutes and opens the completed run detail directly. It displays `SUCCESS`, `FAILED` and `SKIPPED` without inventing per-stage progress not present in metadata.

## Local Development

```powershell
cd frontend
npm.cmd install
$env:VITE_API_BASE_URL = "https://<api-id>.execute-api.us-east-1.amazonaws.com"
npm.cmd run dev -- --host 0.0.0.0
```

The production static bundle is created with `npm.cmd run build` and can be hosted by Vercel or another static host. Set `VITE_API_BASE_URL` to the deployed API URL at build time.

For Vercel, set `frontend` as the Root Directory, use `npm run build`, and keep the output directory as `dist`. The `frontend/vercel.json` file provides rewrites for React Router. The frontend includes `public/examples/retailflow_ventas_ejemplo.xlsx` as a downloadable sales template.

## Backend Deployment

The API requires the existing bucket name and a frontend origin:

```powershell
.\scripts\deploy_api.ps1 `
  -Profile SantiagoDev `
  -Region us-east-1 `
  -StackName retailflow-web-api `
  -Environment dev `
  -BucketName retailflow-etl-santiago-dev-270826 `
  -AllowedOrigin http://localhost:5173
```

Do not use `sam delete` for the ETL stack. The API stack can be removed independently only when explicitly required. The API deployment uses a SAM-managed artifact bucket; that bucket is not the data bucket.

## AWS Verification

```powershell
$base = "https://<api-id>.execute-api.us-east-1.amazonaws.com"
Invoke-RestMethod "$base/runs?limit=20"
Invoke-RestMethod "$base/runs/<run-id>"
Invoke-RestMethod "$base/runs/<run-id>/result?limit=50"
Invoke-RestMethod "$base/runs/<run-id>/errors?limit=50"
Invoke-RestMethod "$base/runs/<run-id>/download"
Invoke-RestMethod "$base/runs/<run-id>/quarantine-download"
```

Use the returned presigned POST fields to upload a supported file. The ETL writes Bronze first, sends rejected records to Quarantine, writes Silver and Gold for valid records, and persists metadata. Re-uploading identical bytes produces a `SKIPPED` run referencing the original run.

## Cost and Security Controls

- The browser never receives AWS access keys.
- Upload keys are generated by the API and restricted to `input/*`.
- Presigned uploads and downloads expire after 300 seconds.
- Upload size is capped at 10 MB.
- The API role reads only metadata, Gold and Quarantine and can write only `input/*`.
- The ETL bucket remains encrypted and blocks public access.
- No provisioned concurrency, queues, databases or extra ETL Lambdas are introduced.
